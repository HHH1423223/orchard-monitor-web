# 山地果园监测平台 · 前端演示版

刺梨园墒情监测与灌溉控制大屏。**当前为演示版：数据由前端模拟引擎生成，未接入真实设备与后端。**

---

## 怎么跑起来

```bash
cd orchard-web

# 首次安装依赖
npm install

# 方式一：开发模式（改代码自动刷新，开发时用）
npm run dev
# 打开 http://127.0.0.1:5173

# 方式二：构建后跑演示服务（演示/交付时用）
npm run build
npm run serve          # 默认 http://127.0.0.1:8080
# 换端口：node serve.js 9000
```

> ⚠️ **不要直接双击 `dist/index.html`** —— 构建产物用 ES module，
> 浏览器对 `file://` 下的模块加载有 CORS 限制，双击会白屏。
> 必须用 `npm run serve` 起本地服务（零依赖，只用到 Node 内置模块）。
> 起好之后终端会同时打印局域网地址，**手机/平板连同一个 WiFi 也能直接看**。

## 五个页面

| 页面 | 路径 | 看什么 |
|---|---|---|
| 实时监测 | `#/monitor` | 4 个 KPI、报警条、9 点水分趋势、园区气象、点位墙、最近报警 |

| 报警中心 | `#/alerts` | 告警列表、处置留痕、阈值规则表 |

## 演示脚本（照着点，5 分钟走完）

1. **登录** → 用 `admin / admin123`
2. **实时监测** → 看 9 条水分曲线的下降趋势与灌溉尖峰；N08 显示"离线 · 滞后 47 分钟"
3. **报警中心** → 看到 N02/N03/N05/N09 水分低于 25% 的告警 → 点开一条 → 填处置说明 → 标记已处置（去看控制页的审计日志会多一条）
4. **灌溉控制** →
   - 点「A 区启动灌溉」→ 确认 → 泵启动、流量出现、倒计时走动
   - 点「模拟流量异常」→ **1 秒内自动停泵**，理由是"空转或堵转"（联锁③）
   - 把现场模式切到「**手动（现场优先）**」→ 再点启动 → **被拒绝**，界面说清原因，审计日志记下"被拒绝 + 原因"（这是最重要的一条）
5. **历史曲线** → 切到"近 24 小时"，多选指标，点「导出 CSV」；点「查看保留策略」看归档设计
6. **退出登录** → 换 `viewer / viewer123` 登录 → 回控制页，所有下发按钮变灰

## 这一版把哪些设计决定落地了

| 决定 | 落在哪 |
|---|---|
| **现场物理开关优先于远程指令** | 控制页「现场模式」开关；切手动后所有下发被拒绝并记原因 |
| **权限简化两级 + 完整审计** | `admin`/`viewer` 两个角色；`store/audit.js` 记录谁/何时/对哪个阀/结果/原因 |
| **三条安全联锁** | 控制页「安全联锁」区：水位<20% 禁启泵、泵超时 30 分钟自动停、流量<0.05 判空转堵转 |
| **3 个上报周期判离线 + 显示滞后时长** | 设备列表「数据滞后」列、点位卡"滞后 N 分钟" |
| **时间以服务器为准** | 每个数据点同时带 `device_ts` 与 `server_ts`，画图按 `server_ts` 排序 |
| **阈值规则可配置** | 报警中心底部「告警规则表」，含冷却期字段 |
| **长期归档一年以上** | 历史页「保留策略」弹窗：47 万行估算、90 天降采样、原始保留 1 年 |
| **不做害虫/病害监测** | 全站无相关内容（本轮决定） |

## 代码结构

```
src/
├── main.js                 入口：注册 Element Plus + 深色主题 + 图标
├── App.vue                 外壳：侧边栏 + 顶栏 + 路由出口 + 时钟
├── router/index.js         hash 路由 + 登录守卫
├── styles/theme.css        深色主题变量与公共类（KPI 卡、点位卡、报警条）
├── store/
│   ├── auth.js             登录态与权限（演示版，账号写死）
│   ├── audit.js            审计日志（演示版存内存）
│   └── monitor.js          监测数据 store —— 页面只跟它打交道
├── mock/
│   ├── devices.js          设备台账、园区信息、分区、告警规则
│   └── simulator.js        数据模拟引擎（日周期 + 随机游走 + 灌溉事件）
├── components/
│   ├── BaseChart.vue       ECharts 封装（含 ResizeObserver 自适应）
│   ├── KpiCard.vue         KPI 卡片
│   └── PointCard.vue       墒情点位卡
├── utils/chart.js          图表主题与公共 option 片段
└── views/                  五个页面
```

**关键设计**：页面不直接碰 `mock/`，只通过 `store/monitor.js` 取数。
以后接真实后端时，**只需要改 `store/monitor.js`**（把模拟引擎换成 `fetch`），
五个页面一行都不用动。这是这一版最重要的可维护性设计。

## 换成真实后端时要改什么

| 现在（演示） | 换成 |
|---|---|
| `mock/simulator.js` 生成数据 | `fetch('/api/telemetry/history')` |
| `monitor.start()` 里的 `setInterval` 推进数据 | 每 10 秒轮询 `/api/telemetry/latest` |
| 登录账号写在 `store/auth.js` | 登录接口 + token + 401 拦截 |
| 审计日志存内存 | 落库（`store/audit.js` 里字段可以直接当表结构） |
| 联锁判断在前端 | **必须移到服务端** —— 前端能绕过的安全规则等于没有安全规则 |
| 控制指令直接改状态 | `POST /api/commands` + 等设备回执（SENT → ACKED / TIMEOUT） |

## 已知不足（诚实清单）

1. **数据是假的**，全站顶部有「演示数据」标识，不要把它当真实数据对外展示。
2. **交互流程未做自动化验证**：页面渲染已逐一截图确认，但按钮点击、弹窗、导出等交互需要人工走一遍上面的演示脚本。
3. **ECharts 打包体积偏大**（约 1 MB，gzip 后 344 KB）—— 后续可改成按需引入。
4. **深色主题只覆盖了用到的组件**，如果新增页面用到别的 Element Plus 组件，可能要补几行变量。
5. **历史曲线纵轴自适应**，只看 6 小时时微小波动会被放大或压平，看起来"很平"是正常现象；想看清变化可以切 24 小时。
6. **没有移动端适配**，只针对桌面/投屏。手机能打开，但布局会挤。
7. **构建产物必须走 HTTP**（见上面那条警告），不能双击打开 —— 演示时记得先 `npm run serve`。
